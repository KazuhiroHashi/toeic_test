# Google Play に出す作業手順

`TOEIC® 総合問題集` の Android 版を Google Play に出すまでの手順。
上から順にやれば終わるように並べてある。各項目の「担当」は次の意味。

- **本人** … 橋野さんが Play Console や GitHub の画面で操作する
- **Claude** … 作業部屋(Claude Code)に頼めばやれる

アプリの中身(問題2,000問・音声・写真)は iOS 版とまったく同じものを使う。作り直しは無い。
**提出と公開のボタンは必ず本人が押す。**

---

## 全体の流れ

| 段階 | 内容 | 目安 |
|---|---|---|
| 0 | 公開してよい状態か確認する | 30分 |
| 1 | ビルドの仕組みを GitHub に入れ、サイズを測る | 1時間 |
| 2 | 署名鍵を作る | 30分 |
| 3 | Play Console でアプリを作る・支払いの設定 | 1時間 |
| 4 | 内部テスト(自分の端末で動作確認) | 半日 |
| 5 | 課金アイテムを作り、購入を試す | 1時間 |
| 6 | ストア掲載情報・アプリのコンテンツ | 2〜3時間 |
| 7 | クローズドテスト 12人×14日(必要な場合だけ) | **最短14日** |
| 8 | 製品版の審査に出す → 公開 | 数日 |

段階7が必要かどうかで、全体の長さが2週間以上変わる。だから段階0で先に確かめる。

### □ 0-1. アカウントの種類を確かめる

Play Console → 左下の「設定」→「デベロッパー アカウント」→「アカウントの詳細」

- **個人**か**組織**か
- 前回「Google の審査が通った」と聞いたものが、ここでいう本人確認なのか、
  組織としての確認なのかをはっきりさせる

### □ 0-2. ストアに出る名前を確かめる

同じ画面の **デベロッパー名** が `Bridge AI` になっていること。

本名(`Kazuhiro Hashino`)のままなら、**ここで止める。**
STATUS.md の方針どおり、本名を公開の場に残さないため。

あわせて、ストアのアプリページに出る「デベロッパーの連絡先」
(メール・住所・電話)に何が表示される設定かも見る。
有料の商品を売るアカウントは住所の公開を求められる場合がある。
**本名や自宅住所が出る設定なら、公開前に相談する。**

### □ 0-3. クローズドテストの要件を確かめる

2023年11月以降に作った**個人**アカウントは、製品版に出す前に
「**12人以上**が**14日間連続**でテストに参加」が必要。**組織アカウントは対象外。**

ダッシュボードに「製品版へのアクセス権を申請」の項目や、
テスター数・日数のカウンターが出ていれば要件あり。出ていなければ対象外。
**思い込まず、画面の表示で判断する。**

要件ありの場合、テスターを12人集める必要がある(家族・友人で可。Google アカウントが要る)。
早めに声をかけておくと、段階7で待たずに済む。

## 段階1:ビルドの仕組みを入れ、サイズを測る

### □ 1-1. Android 対応の変更を GitHub に入れる(Claude → 本人が確認)

作業部屋に用意してある変更:

| ファイル | 内容 |
|---|---|
| `tools/build_app.sh` | `android` を渡すと Android 用の目印を書く。**引数なしは今までどおり iOS** |
| `js/app.js` | 購入まわりの文言を出し分け(App Store / Google Play、Apple ID / Google アカウント) |
| `package.json` ほか | Android 用の部品(`@capacitor/android`)を追加 |
| `tools/setup_android.js` | 課金の権限・署名・バージョン番号の設定を入れる |
| `tools/make_android_icons.py` | アイコンを実物に差し替える |
| `.github/workflows/android.yml` | AAB(Play に上げるファイル)を作る。**作るだけで、提出はしない** |

iOS 版の動作・ビルド手順は変わらない。

Claude がブランチに push → 本人が GitHub で中身を見て main に入れる(マージ)。
**Actions のボタンは、ファイルが main に入るまで画面に出ない。**

### □ 1-2. 一度ビルドしてサイズを測る(本人)

1. GitHub → Actions →「Android build (AAB)」→ Run workflow
2. バージョンは `1.0` のままでよい
3. 10〜15分で終わる

**署名鍵がまだ無くても実行できる。**この回はサイズを測るだけが目的。

ログの「配信される大きさを測る」に出る **MAX の数字** を見る。

- **209,715,200 未満(200MB 未満)なら合格。**手元の見積もりは約170MB
- 超えていたら段階1-3へ。収まっていたら段階2へ

失敗した場合は、ログの赤い行を作業部屋に貼れば Claude が直す。

### □ 1-3. (200MB を超えたときだけ)対策を選ぶ

| 案 | 手間 | 代償 |
|---|---|---|
| A. Android だけ音声を 48kbps に下げる | 半日 | 音が少しこもる。試聴して決める。iOS は 64kbps のまま |
| B. 音声を別配信(Play Asset Delivery) | 数日 | 音質は同じ。ただし iOS と仕組みが分かれ、以後の修正が二度手間 |

## 段階2:署名鍵(アップロード鍵)を作る(本人)

Android のアプリは、作った人の鍵で署名してから Play に上げる。
**この鍵とパスワードを無くすと、更新が出せなくなる**(申請すれば差し替えはできるが手間)。

### □ 2-1. 鍵を作る

パソコンに Java(JDK)が入っていれば、次のコマンドを1回だけ実行する。
入っていなければ [Adoptium](https://adoptium.net/) から JDK 21 を入れる。

```
keytool -genkeypair -v -keystore upload-key.jks -alias toeic-upload -keyalg RSA -keysize 2048 -validity 10000
```

パスワードと名前などを聞かれる。名前は `Bridge AI` でよい(ストアには出ない)。

**`upload-key.jks` とパスワードは、2か所以上に控える**(パスワード管理アプリ+クラウドなど)。

### □ 2-2. GitHub に登録する

GitHub → リポジトリの Settings → Secrets and variables → Actions → New repository secret

| 名前 | 中身 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 鍵ファイルを文字にしたもの(下のコマンド) |
| `ANDROID_KEYSTORE_PASSWORD` | 鍵ファイルのパスワード |
| `ANDROID_KEY_ALIAS` | `toeic-upload` |
| `ANDROID_KEY_PASSWORD` | 鍵のパスワード(聞かれなかった場合は上と同じ) |

鍵ファイルを文字にするコマンド(Windows の PowerShell。結果がクリップボードに入る):

```
[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-key.jks")) | Set-Clipboard
```

### □ 2-3. 署名付きでビルドし直す

Actions →「Android build (AAB)」→ Run workflow(バージョン `1.0`)。
終わったら、画面下の **Artifacts** から次の2つを落とす。

- `toeic-1.0-…-aab` … zip を開くと `app-release.aab` が入っている
- `play-store-icon-512` … ストア用アイコン(段階6で使う)

## 段階3:Play Console でアプリを作る(本人)

### □ 3-1. アプリを作成する

Play Console →「アプリを作成」

| 項目 | 入力 |
|---|---|
| アプリ名 | `TOEIC® 総合問題集` |
| デフォルトの言語 | 日本語 |
| アプリ / ゲーム | アプリ |
| 無料 / 有料 | **無料**(課金はアプリ内で行う) |

宣言のチェックボックスに同意して作成。

**無料で作ったアプリは、あとから有料アプリに変えられない。**
このアプリは本体無料+アプリ内課金なので、無料で正しい。

### □ 3-2. お支払いプロファイルを用意する

アプリ内課金で売上を受け取るために必要。
Play Console → 設定 →「お支払いプロファイル」

- 名前・住所・銀行口座(楽天銀行で可)を登録
- **ここで入れた名前が購入者のレシートに出る可能性がある。**
  販売者名の表示がどうなるかを画面で確認し、本名が出るなら相談する

これが済んでいないと、段階5で課金アイテムを作れない。

## 段階4:内部テスト(本人)

まず自分の端末で動くかを見る。内部テストは審査がほぼ無く、すぐ配れる。

### □ 4-1. テスターを登録する

テスト →「内部テスト」→「テスター」タブ → メーリングリストを作り、
自分の Google アカウントを入れる。

### □ 4-2. AAB を上げる

「新しいリリースを作成」

- 初回は **Play アプリ署名** を聞かれる →「Google に生成させる」(推奨のまま)。
  段階2で作った鍵は「アップロード鍵」として扱われる
- `app-release.aab` をアップロード
- リリース名はそのまま、リリースノートは「初回テスト」程度でよい
- 保存 → 確認 →「内部テストとして公開」

※ここでいう「公開」はテスターへの配布だけで、一般には出ない。

### □ 4-3. 端末で確かめる

テスターのタブにある参加用リンクを Android 端末で開き、Play からインストール。

- □ 起動する。アイコンが青い本物になっている
- □ セット1が無料で全部使える
- □ リスニング音声が鳴る(機内モードでも鳴る)
- □ Part1 の写真が出る
- □ セット2〜10 に鍵がかかっている
- □ 購入ボタンを押すと「商品が見つからない」系のエラーになる
  ← 段階5の前なので正常

## 段階5:課金アイテム(本人)

**AAB を一度上げた後でないと、課金アイテムの画面が使えない。**だから段階4の後にやる。

### □ 5-1. 商品を作る

Play Console → 収益化 → 商品 →「1回限りの商品」(画面によっては「アプリ内アイテム」)

| 項目 | 入力 |
|---|---|
| 商品 ID | `com.bridgeaitokyo.toeic.unlockall` |
| 名前 | `全セット解放` |
| 説明 | `セット2〜10(1,800問)をすべて解放します。買い切りで、追加の料金はかかりません。` |
| 価格 | ¥680 |
| 有効化 | 有効にする |

**商品 ID は一字一句このとおりに。**アプリ側と1文字でも違うと購入画面が出ない。
**一度作った商品 ID は削除しても二度と使えない。**

「消費型」と「非消費型」を選ぶ欄が出たら、**非消費(1回だけ買うもの)**。

### □ 5-2. ライセンス テスターを登録する

設定 →「ライセンス テスト」→ 自分の Google アカウントを追加。
これで、テスト購入しても実際にはお金がかからない。

### □ 5-3. 購入を試す

内部テストのアプリで:

- □ 購入ボタンに「¥680」が表示される(反映に数時間かかることがある)
- □ 購入できて、セット2〜10 が開く
- □ アプリを削除 → 入れ直す →「購入を復元する」で再び開く
- □ 3日たっても自動で返金されていない(Play の注文管理で確認)

最後の項目は、購入の確定処理が正しく動いているかの確認。
プラグインが自動でやる設計なので、通常は問題ない。

## 段階6:ストア掲載情報とアプリのコンテンツ(本人、文案は Claude)

### □ 6-1. メインのストア掲載情報

Play Console → 拡大 →「メインのストアの掲載情報」

| 項目 | 条件 | 用意 |
|---|---|---|
| アプリ名 | 30文字まで | `TOEIC® 総合問題集` |
| 簡単な説明 | 80文字まで | App Store のサブタイトル・説明から作る(Claude) |
| 詳しい説明 | 4,000文字まで | App Store の説明文を流用(Claude が調整) |
| アプリのアイコン | 512×512 PNG | 段階2-3の `play-512.png` |
| **フィーチャー グラフィック** | **1024×500(必須)** | **新しく作る必要がある**(Claude が作れる) |
| スマホのスクリーンショット | 2〜8枚、長辺は短辺の2倍まで | 下の注意を参照 |

**スクリーンショットの注意:**iOS 用の5枚は 1320×2868 で、縦が横の2.17倍ある。
Play の上限(2倍)を超えるので**そのままでは上げられない。**
上下に余白を付けて 1434×2868 にするか、Android 端末で撮り直す。
変換は Claude ができる(画像を作業部屋に渡す)。

説明文に入れてはいけないもの:「No.1」「最高」など根拠のない比較、
ほかのアプリ名、検索用のキーワードの羅列。
**TOEIC の商標の免責文(ETS の登録商標であること)は説明文の末尾に入れる。**

### □ 6-2. アプリの設定

拡大 →「ストアの設定」

- カテゴリ:**教育**
- メール:`contact@bridge-ai-tokyo.com`
- ウェブサイト:`https://toeic.bridge-ai-tokyo.com/`

### □ 6-3. アプリのコンテンツ(申告)

Play Console → ポリシー →「アプリのコンテンツ」。全部「完了」にする。

| 申告 | 答え |
|---|---|
| プライバシー ポリシー | `https://bridge-ai-tokyo.com/privacy.html` |
| 広告 | 広告を含まない |
| アプリのアクセス権 | 特別なアクセス権なしで全機能を利用できる(ログインが無いため) |
| コンテンツのレーティング | 質問票に答える。カテゴリは「その他」/教育。暴力・性的表現などは全部「いいえ」 |
| ターゲット ユーザー | **13歳以上**を選ぶ。13歳未満を含めると「ファミリー向け」の別審査になる |
| データ セーフティ | 「データを収集または共有しない」。課金は Google が処理する |
| 政府機関のアプリ | いいえ |
| 金融取引機能 | なし |
| 健康 | なし |

データ セーフティは App Store の「データを収集しない」と同じ内容にそろえる。
食い違うと、後から違反の通知が来ることがある。

### □ 6-4. 国と価格

製品版 →「国 / 地域」→ **日本のみ**。

EU を含めると、デジタルサービス法の関係で連絡先(氏名・住所)の公開を
求められる。STATUS.md の方針どおり当面は日本のみ。

## 段階7:クローズドテスト(段階0-3で要件ありだった場合だけ)

### □ 7-1. テスターを集める

テスト →「クローズド テスト」→ トラックを作り、12人以上の
Google アカウント(Gmail アドレス)を登録する。

### □ 7-2. AAB を上げてテストを始める

内部テストと同じ AAB をクローズドテストにも上げる。
こちらは**審査がある**(数時間〜数日)。

### □ 7-3. 14日間待つ

- テスターは参加用リンクから「テスターになる」を押し、**インストールして14日間消さない**
- 途中で12人を下回るとカウントが止まることがある。13〜15人集めておくと安全
- 期間中に1回くらいは修正版を上げ、フィードバックを受けた形にしておくと、
  次の申請の質問に答えやすい

### □ 7-4. 製品版へのアクセスを申請する

ダッシュボード →「製品版へのアクセス権を申請」。テストの内容や
集まった意見について質問に答える(文案は Claude が手伝える)。
結果が出るまで数日。

## 段階8:製品版の審査 → 公開(本人)

### □ 8-1. 公開の管理をオンにする

Play Console → 公開の概要 →「**公開の管理**」をオン。

これで、**審査が通っても自動では公開されない。**
本人が「公開」を押すまで止めておける(App Store の「手動でリリース」と同じ)。

### □ 8-2. 製品版のリリースを作って審査に出す

製品版 →「新しいリリースを作成」→ AAB を選ぶ(内部テストのものを流用できる)
→ リリースノート →「審査に送信」。

審査は数時間〜1週間程度。初回は長めになりやすい。
却下された場合はメールと Play Console に理由が出るので、作業部屋に貼る。

### □ 8-3. 公開する

審査が通ったら、段階0-2の名前・連絡先表示をもう一度だけ確かめてから、
「公開の概要」→「変更を公開」。

---

## その後(更新を出すとき)

1. コードを直して main に入れる
2. Actions →「Android build (AAB)」→ バージョン番号を上げて実行
   (versionCode は自動で増える)
3. 製品版 → 新しいリリース → AAB を上げて審査に送信

iOS 版と同じ修正を出すなら、iOS の Actions も回す。中身は共通。

---

## やってはいけないこと

- **提出・公開を機械に任せない。**ボタンは本人が押す
- 本名がストアに出る状態で公開しない
- 署名鍵(`upload-key.jks`)とパスワードを git やチャットに貼らない
- 課金アイテムの ID を打ち間違えたまま作らない(二度と使えない)
- アプリの中から note の販売ページへ誘導しない(Play も Apple も禁止)
